# アーキテクチャ

## 想定フロー

```text
コンテンツ編集者 → microCMS → Webhook → Cloudflare Pagesのビルド → Astro静的サイト
```

## 役割分担

| サービス | 役割 |
| --- | --- |
| microCMS | サイトコンテンツとメディアを保存・編集する。 |
| GitHub | ソースコードを保存し、プレビューまたは本番デプロイを起動する。 |
| Cloudflare Pages | ビルドを実行し、生成済み静的ファイルをホストする。 |
| Astro | テンプレートとmicroCMSコンテンツを静的HTMLへ変換する。 |

## 必須制約

- 公開リクエストは静的ファイルを返し、データベースを必要としてはならない。
- ブラウザからmicroCMSを直接呼び出してはならない。
- microCMSの秘密情報はローカル開発用環境変数とCloudflare Pagesの環境変数にのみ置く。
- コンテンツ更新時はmicroCMS Webhookで静的ビルドを起動する。
- 製品カテゴリ、一覧、詳細を静的に生成できるよう、製品データをmicroCMSで管理する。
- 製品画像とダウンロード資料は、所有権と公開許可を確認した後にのみ移行する。

## 多言語URL

- 中国語（`zh`）をデフォルト言語とし、正規URLはルート直下の`/`、`/about/`、`/products/`、`/contact/`とする。
- 日本語は`/ja/`、英語は`/en/`を接頭辞とする。各言語の製品詳細は同じ`slug`を使い、ビルド時に静的生成する。
- 既存の`/zh/`配下は中国語の互換URLとして維持し、正規URLはルート直下の中国語URLを指す。
- すべての言語ページは、対応する中国語・日本語・英語の`hreflang`と、中国語を指す`x-default`を出力する。

## 保留中の判断

- plain CSSまたはTailwind CSSの採用。
- 問い合わせフォーム事業者またはメール問い合わせ方式。
- アクセス解析事業者。
- 検索エンジンおよびSNS向けメタデータの要件。
- 製品検索の要件。初回リリースでは実行時検索より静的カテゴリページを優先する。
